# 端侧（浏览器内）向量化与 INT8 / FP16 量化

> 结论来源：`stepfun/TECH_REPORT.md`，全部为本机（Edge headless + WASM）实测数据。

## 1. 模型选择

| 项 | 值 |
| --- | --- |
| 模型 | `Xenova/bge-small-zh-v1.5`（bge-small-zh-v1.5 的 ONNX 转换） |
| 固定版本 | revision `75c43b069aac4d136ba6bc1122f995fedcfd2781` |
| 向量维度 | 512，cosine，L2 归一化 |
| 运行时 | `@huggingface/transformers` 3.8.1（Transformers.js） |

选 bge-small 而不是 bge-base 的原因：端侧场景首屏体积优先，512 维在中文短文本检索上
与 768 维基座差距很小，但包体积与推理耗时低一个数量级。

## 2. 量化体积与质量

| 权重 | 体积 | 压缩比 |
| --- | --- | --- |
| FP32 | 90.5 MiB | 1.00x |
| FP16 | 45.3 MiB | 2.00x |
| INT8 | 22.8 MiB | 3.97x |

量化质量（同一浏览器、同一 12 段语料、6 条查询，精确余弦 Top-5）：

| 指标 | INT8 | FP32 |
| --- | --- | --- |
| Recall@5 | 0.917 | 0.917 |
| Top-5 重合度 | 96.7% | — |

结论：**INT8 没有损失召回**，与 FP32 的差异只来自一条边界样本的排名互换。
因此端侧默认加载 INT8，只有在需要对照基线时才拉 FP32。

## 3. 后端选择策略

1. 检测 `navigator.gpu.requestAdapter()`；
2. 可用 → 加载 FP16，`device: "webgpu"`；
3. 初始化或推理抛异常 → 捕获后加载 INT8，`device: "wasm"`，界面徽标显示当前后端。

实测（WASM + INT8，Edge headless）：模型加载 594 ms（浏览器缓存命中），
12 个片段向量化 748 ms，约 2 447 字符/秒；首次加载需下载 22.8 MiB。

## 4. 离线与线程

- 模型放在 `public/models/`，ONNX Runtime 的 `.wasm`/`.mjs` 通过 `npm run build`
  前复制到 `public/ort/`，并设置 `env.backends.onnx.wasm.wasmPaths`，**不请求 jsDelivr**
  （保证离线可用，也避免评测环境无外网导致加载失败）。
- `numThreads = 1`：不依赖 COOP/COEP 响应头，避免部署时被浏览器拦下。

## 5. 为什么 StepFun 题禁止云端推理

StepFun 赛题要求「文档向量化与查询向量化必须在浏览器本地完成，存储和混合检索必须由
seekdb 完成」。因此：

- embedding 一定在浏览器内算，不能退化成调云端 API；
- 向量写入与检索在 seekdb 内核完成，不能把向量存到别的库再在客户端过滤；
- 评测时不能依赖任何外部网络请求（模型权重已本地化）。

## 6. 常见坑

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 首屏白屏很久 | 在下载 22.8 MiB INT8 | 提前预热 + 显示进度 |
| WebGPU 下报错 | 驱动不支持某算子 | 捕获异常回退 WASM |
| 检索结果和基线差很多 | 查询向量没做 L2 归一化 | 入库与查询统一归一化 |
| 写入后查不到 | HNSW 索引未刷新 | `refresh_index()` / `dbms_index_manager.refresh()` |
