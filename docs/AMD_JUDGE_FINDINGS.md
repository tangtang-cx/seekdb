## 固定开销：快照里那份重复的向量

cuVS 的快照文件在 `include_dataset = true` 时**已经含有完整数据集**（`Saving CAGRA index with dataset`），
适配层却把同一份原始向量又抄了一遍进索引流：索引体积从
`ids 2MB + vectors 256MB + cuVS 快照 384MB = 642MB` 降到 `ids 2MB + cuVS 快照 384MB = 386MB`。

- 快照格式用 `reserved` 字段区分：0 = 旧布局（带向量段），1 = 紧凑布局（无向量段），
  **两种布局都能正确读回**（旧索引文件不会读错）。
- 紧凑布局下 `buf_vecs_` 为空，因此只有在「GPU 索引仍在」时才允许重新序列化；
  需要重建索引而没有向量缓冲时退回 VSAG 格式（与原逻辑一致）。
- 格式往返由本地测试覆盖（紧凑 / 旧布局 / 混读三种情形，13 项断言）。

## 判题实测（13 次）

| 版本 | 参数 | build | query | 结果 |
|---|---|---|---|---|
| v9 | 128/128/50 设备张量 | 1.647x | 1.691x | 12.356 |
| v16 | 128/128/50 + memfd | 1.715x | 1.704x | 12.874 |
| v21 | 160/48 + 参考建图 + 快查询 | 2.538x | 1.785x | **17.871** |
| v23 | 同上 + 128维 niter3 | 2.309x | 1.722x | 16.666 |
| v24 / v26 / v29 / v31 | itopk 1024 或 igd==gd | — | — | gpu_path |
| v27 | gd 64 / igd 128 / niter 36 | — | — | 召回判负 |
| v34 | gd 96 / igd 128 / niter 36 | — | — | 召回判负（管线已正常） |
| v36 | niter 32 + itopk 2048 + multi-CTA | — | — | 任务级执行失败 |

同一份配置两次测得 2.538 与 2.309 → build 噪声约 ±10%（对手那边 160/40 也测到比模型低 31%）。
v27 与 v34 说明：**recall@10 对输出宽度极其敏感**，gd 64 与 gd 96 都判负，只有与基线同宽的 gd 128 才安全。

## 约束下界（全部来自判题实测）

1. 输出宽度必须 = 基线的 128（gd 96 / gd 64 都召回判负）
2. 候选宽度必须 > 输出宽度（igd == gd 会丢 GPU 路径），故 igd = 160
3. 搜索候选池必须 = 512（>512 的每次都丢 GPU 路径，multi-CTA + 2048 直接任务级失败）
4. 搜索预算既然被锁死，召回只能由图承担 → 轮数是唯一旋钮
5. igd 160 时对手实测：niter 40 通过、niter 32 召回判负 → 安全区在 34~40，而 build ≥3.0 需要 niter ≲34

## 收口方案

```
第 1 枪 (v37)   256维: gd 128 / igd 144 / niter 36 / itopk 512 / width 4
第 2 枪 (v38)   256维: gd 128 / igd 144 / niter 34 / itopk 512 / width 4
备选   (v39)   256维: gd 128 / igd 160 / niter 36 / itopk 512 / width 4
兜底档         256维: gd 128 / igd 160 / niter 48 / itopk 512 / width 4
探测           建完用生产同款搜索参数跑一次查询；失败即自动重建兜底档
```

为什么选 igd 144：判题实测显示**候选宽度越小召回越好**（igd128/niter40 → Δ−0.0002，
igd160/niter40 → Δ−0.0018），而建图耗时 ∝ igd × niter。144 是两个已验证点之间的插值，
两头都占优：

| igd | niter | 建图耗时 | 预计 build | 预计召回 Δ（判题口径） |
|---|---|---|---|---|
| 160 | 48 | 17.0 s | 2.42（实测） | ≈−0.0024（通过） |
| 160 | 36 | 13.9 s | 2.85~2.99 | ≈−0.0043（贴边） |
| **144** | **36** | **12.9 s** | **3.07~3.18** | **≈−0.0032（安全）** |
| 144 | 34 | 12.4 s | 3.20~3.31 | ≈−0.0046（贴边） |

即：igd 144 + niter 36 同时把 build 推过 3.0 封顶线、把召回留在预算内。
剪枝合法性不受影响（候选宽度仍严格大于输出宽度，且"每点有效邻居数"是数据属性、与 igd 无关）。
任何“建图/搜索不可用”都不会再变成 0 分，最坏退化为 17.9。
