# AMD 赛道（600072 / 800509）判题问题总表与最终版设计依据

| # | 判题现象 | 根因 | 最终版对策 |
|---|---|---|---|
| F1 | `failMsg=3`（14 秒即失败） | hipVS 的 `hipHostMalloc` 是 3 参数，`cudaMallocHost` 写法 2 参数 → 桥接编译不过 | `sk_host_malloc()` 按平台分派（已修） |
| F2 | `failMsg=4` 克隆失败 | 仓库地址被截断/与报名登记不一致 | 用登记原串（含 token 的 144 字符） |
| F3 | `query_regression` | 查询慢于基线 | 查询侧保持常驻 worker + 复用缓冲（1.69~1.79x） |
| F4 | `recall@10/@100_baseline_delta` | 建图太弱：niter 30 / ITERATIVE_CAGRA_SEARCH / AUTO_SELECT | 一律 `NN_DESCENT` + 足够轮数 |
| F5 | `recall@10_minimum`、`recall@100_minimum` | 图太稀 / 搜索候选池太小 | 输出宽度保持基线值 128；搜索候选池放大到远超基线 |
| F6 | `relative_vram_limit` | 中间图过宽（igd 256） | igd 160，比基线（256）小 |
| F7 | `gpu_path` | 两种独立机制：<br>**A** 搜索候选池 > 512（默认 single-CTA 内核上会失败）<br>**B** 候选宽度 == 输出宽度 | A: 候选池固定 512（= 基线值）<br>B: igd 160 > gd 128，留 32 格剪枝余量<br>**再加**：建完立刻用生产同款搜索参数探测，失败自动重建 128/160/48 兜底档 |
| F8 | 同一 SHA 重投结果不同 | 判题本身有 ±10% 噪声与门槛抖动 | 参数取在噪声之外（build 目标 3.0~3.2 而非贴线） |
| F9 | 任务级「执行失败」（非门槛失败） | 用了判题机那版 hipVS 头文件里没有的符号（`cuvsCagraSearchAlgo.algo`）| 只用基线 C API；外部符号集与已通过的 v21/v23 完全一致 |

## 判题实测（13 次）

| 版本 | 参数 | build | query | 结果 |
|---|---|---|---|---|
| v9 | 128/128/50 设备张量 | 1.647x | 1.691x | 12.356 |
| v16 | 128/128/50 + memfd | 1.715x | 1.704x | 12.874 |
| v21 | 160/48 + 参考建图 + 快查询 | 2.538x | 1.785x | **17.871** |
| v23 | 同上 + 128维 niter3 | 2.309x | 1.722x | 16.666 |
| v24 / v26 / v29 / v31 | itopk 1024 或 igd==gd | — | — | gpu_path |
| v27 | gd 64 / igd 128 / niter 36 | — | — | 召回判负 |
| v34 | gd 96 / igd 128 / niter 36 | — | — | 召回判负（管线已正常） |
| v36 | niter 32 + itopk 2048 + multi-CTA | — | — | 任务级执行失败 |

同一份配置两次测得 2.538 与 2.309 → build 噪声约 ±10%（对手那边 160/40 也测到比模型低 31%）。
v27 与 v34 说明：**recall@10 对输出宽度极其敏感**，gd 64 与 gd 96 都判负，只有与基线同宽的 gd 128 才安全。

## 约束下界（全部来自判题实测）

1. 输出宽度必须 = 基线的 128（gd 96 / gd 64 都召回判负）
2. 候选宽度必须 > 输出宽度（igd == gd 会丢 GPU 路径），故 igd = 160
3. 搜索候选池必须 = 512（>512 的每次都丢 GPU 路径，multi-CTA + 2048 直接任务级失败）
4. 搜索预算既然被锁死，召回只能由图承担 → 轮数是唯一旋钮
5. igd 160 时对手实测：niter 40 通过、niter 32 召回判负 → 安全区在 34~40，而 build ≥3.0 需要 niter ≲34

## 收口方案

```
v37（第一枪）  256维: gd 128 / igd 160 / niter 36 / itopk 512 / width 4
v38（第二枪）  256维: gd 128 / igd 160 / niter 34 / itopk 512 / width 4
兜底档        256维: gd 128 / igd 160 / niter 48 / itopk 512 / width 4
探测          建完用生产同款搜索参数跑一次查询；失败即自动重建兜底档
```

- v37 的 build 预计 2.85~2.96（±10% 噪声下约四成机会直接过 3.0 拿满 14 分），召回预计 −0.0043，仍在 0.005 预算内
- v38 的 build 预计 2.95~3.08，召回预计 −0.0049（贴边但仍在预算内）
- 任何“建图/搜索不可用”都不会再变成 0 分，最坏退化为 17.9
