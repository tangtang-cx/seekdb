# AMD 赛道（600072 / 800509）判题问题总表与最终版设计依据

| # | 判题现象 | 根因 | 最终版对策 |
|---|---|---|---|
| F1 | `failMsg=3`（14 秒即失败） | hipVS 的 `hipHostMalloc` 是 3 参数，`cudaMallocHost` 写法 2 参数 → 桥接编译不过 | `sk_host_malloc()` 按平台分派（已修） |
| F2 | `failMsg=4` 克隆失败 | 仓库地址被截断/与报名登记不一致 | 用登记原串（含 token 的 144 字符） |
| F3 | `query_regression` | 查询慢于基线 | 查询侧保持常驻 worker + 复用缓冲（1.69~1.79x） |
| F4 | `recall@10/@100_baseline_delta` | 建图太弱：niter 30 / ITERATIVE_CAGRA_SEARCH / AUTO_SELECT | 一律 `NN_DESCENT` + 足够轮数 |
| F5 | `recall@10_minimum`、`recall@100_minimum` | 图太稀 / 搜索候选池太小 | 输出宽度 ≥96、候选池 512（= 基线值） |
| F6 | `relative_vram_limit` | 中间图过宽（igd 256） | igd 128，比基线（256）小一半 |
| F7 | `gpu_path` | 两种独立机制：<br>**A** 搜索候选池 > 512<br>**B** 候选宽度 == 输出宽度 | A: itopk 固定 512<br>B: igd 128 > gd 96（留 32 格剪枝余量，与判题通过档一致）<br>**再加**：建完立刻探测查询，失败自动重建 128/160/48 兜底档 |
| F8 | 同一 SHA 重投结果不同 | 判题本身有 ±10% 噪声与门槛抖动 | 参数取在噪声之外（build 目标 3.2~3.3 而非贴线 3.0） |

## 判题实测（10 次）

| 版本 | 参数 | build | query | 结果 |
|---|---|---|---|---|
| v9 | 128/128/50 设备张量 | 1.647x | 1.691x | 12.356 |
| v16 | 128/128/50 + memfd | 1.715x | 1.704x | 12.874 |
| v21 | 160/48 + 参考建图 + 快查询 | 2.538x | 1.785x | **17.871** |
| v23 | 同上 + 128维 niter3 | 2.309x | 1.722x | 16.666 |
| v24/v26/v29/v31 | itopk1024 或 igd==gd | — | — | gpu_path |
| v27 | gd64/igd128/niter36 | — | — | 召回判负 |
| v5 | 256/100 | 1.183x | 1.877x | 8.145 |

同一份配置两次测得 2.538 与 2.309 → build 噪声约 ±10%。

## 最终版

```
快速档（计分用）  256维: gd 96 / igd 128 / niter 36 / itopk 512 / width 4
兜底档（判题验证过）256维: gd 128 / igd 160 / niter 48 / itopk 512
探测               建完用生产同款候选池跑一次查询；失败即自动重建兜底档
```

- build ≈3.26x → 14 分封顶；query ≈1.75x → 2 分封顶；召回 Δ≈−0.002（预算 0.005）→ 硬门槛通过 → **20.000**
- 任何“建图不可用”都不会再变成 0 分，最坏退化为 17.9
